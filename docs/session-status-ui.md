# 会话状态的视觉语义（设计建议）

当前后端运行状态只有 Starting、Idle、Working、Stopped、Failed。
未读是前端的阅读属性，归档是独立的列表属性，不应与运行状态互相替换。
生命周期约束是“归档必然停止，停止不必然归档”；恢复成功会启动原会话并解除归档。
以下是下一步统一组件的设计方向，不表示所有状态已实现。

| 层级 | 状态 | 建议图形 | 含义 |
| --- | --- | --- | --- |
| 运行 | 启动中 | 转圈 | 正在建立运行环境，尚不可正常交互 |
| 运行 | 就绪且已读 | 不显示特殊状态 | 后端可用，当前没有执行任务，不占用用户注意力 |
| 运行 | 工作中 | 活动波形 | Agent 正在处理请求；不是可点击的“播放”按钮 |
| 运行 | 已停止 | 灰色熄灭灯 | 运行实例已结束，不使用容易看成按钮的方块 |
| 运行 | 失败 | 红色警告三角 | 运行或持久化失败；提示具体原因 |
| 注意事项 | 等待用户 | 温和的暖色亮点 | 需要用户回应，不使用感叹号或错误警告视觉 |
| 阅读属性 | 有未读回复 | 独立的小圆点 | 有新内容，不覆盖工作中／失败等运行状态 |
| 列表属性 | 已归档 | 归档盒 | 已停止并隐藏于普通列表，可恢复原会话 |

统一约束：

- 状态是被动指示，使用普通光标和状态提示；操作才有按钮、hover 背景和手形光标。
- 播放三角表示“启动”动作，不表示“正在运行”；方块只用于停止操作，
  已停止状态使用熄灭灯。所有灯态都没有按钮外框、点击行为或交互反馈。
- 图形与颜色共同表达，不能只靠颜色区分。动画仅用于确实进行中的过程，并尊重减少动态效果设置。
- 断线是连接状态，不能把所有会话改成失败或停止。尚未加载的 Agent 原生记录也不能猜为已停止。
- 服务器地址和 gRPC 连接状态独立显示于侧栏底部，与输入框底部工具栏对齐。
- 已归档且停止时只提供恢复操作，不再并列启动；草稿、队列等待／暂停不属于 Agent 运行状态。
- 状态名称、图形、颜色、尺寸、提示在共享组件中定义，侧栏与会话管理不维护各自的映射。

## 数据边界

当前“启动中”和“工作中”共用转圈，就绪且已读留空、停止灰灯已在共享组件实现；
侧栏只在空闲时以小圆点表示未读，会话管理没有阅读游标。
因此下一步不应只换几个 SVG：需要把运行状态与未读属性拆开，明确所有入口的读取来源。

审批／输入／认证面板和 ACP 前台状态能提供部分“等待用户”信息，但这些信息不在
通用 `SessionSnapshot` 中。会话管理不能只看 `Working` 就推断正在思考或等待审批。
要让侧栏、历史和后台会话一致，应先补齐可观察的注意事项状态；未知时不显示推测性标记。

# BasG 设置界面

设置窗口展示配置，智能体添加与安装属于独立流程。不要把安装目录、注册流程或会话选项混进配置页面。

## 配置作用域

- **BasG · 前端**：本机的外观、字体和输入行为。由 BasG 启动时选择的配置存储读取，自动保存 `appearance`，不修改后端智能体注册。
- **bas · 后端**：当前连接的 bas 服务及其智能体配置。服务地址是上下文，不是会话中的智能体选择器。目前不能在设置里切换服务。
- 默认安装可以共用一个 JSON 文件，但两个作用域独立选择存储并按字段保存。前端的 `--settings-file` 不应决定另一个本机 bas 服务的注册文件。
- 后端文件只有在本机服务报告可写、路径已由服务解析为绝对路径、且存储来源可以确认时才能编辑。远程、命令行覆盖和无法验证的存储保持只读；远程报告的路径不能当作本机路径打开。

## 页面结构

- 内容区左上角随配置归属显示上下文：前端页面只显示本机设置，不显示或查询后端地址；后端页面才显示当前 bas 服务。这里不是前端／后端页面切换器，后端切换尚未支持。
- 前端和后端配置页面通过左侧导航进入；页面自己不再在页头或页脚重复显示文件路径。
- 右上角的“编辑配置文件”始终针对当前作用域，完整路径放在提示中；未验证的后端禁用此入口。
- 导航按前端与后端分组。外观使用平铺的分区与设置行；智能体配置只显示已注册智能体。
- 左侧导航只包含配置页面和配置项，不放添加／安装操作。“添加智能体”和刷新属于“智能体”章节，放在该章节标题右侧；全局顶部只保留后端上下文与配置文件入口。
- 添加操作打开独立原生窗口。安装目录与自定义注册表单在该窗口中呈现，与配置页面共享后端状态，但不共享页面显示模式。
- 配置与安装页面复用同一个智能体条目组件，统一图标、名称、已安装版本与状态。条目操作使用同规格 icon button，hover 与无障碍名称共用简短说明；安装成功清除进度提示，稳定状态显示“已安装”。

## 统一视觉规则

- 常规界面文字使用 `ui::SMALL`，消息和代码沿用独立的内容字号。
- 不依赖组件的尺寸枚举推断文字字号：控件可能在内部覆盖继承样式。回归测试应检查实际渲染的标签。
- 所有原生窗口从 `theme::window_root` 创建，窗口控制按钮复用同一个第一方组件。窗口只选择操作与关闭回调，不自行定义按钮与图标尺寸。
- Zed 的设置截图用于理解布局与交互，不复制或链接其 GPL 上层 UI 实现。

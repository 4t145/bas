# 原版 UI 依赖基线

## 智能体动作、工作目录能力与后端池配置

用户截图复现：更新与可用性检查都使用刷新图标，悬停检查按钮时更难区分动作；
不支持多工作目录的 Agent 仍显示附加文件夹入口；ACP 回收与预热策略只有文件配置，
后端设置导航没有对应页面。更新改用向上升级图标，检查使用与连接页一致的活动检测图标。
工作目录入口仅在初始化明确声明 additionalDirectories 且能 load／resume 时展示，
忙碌只禁用操作，不隐藏已支持功能。后端增加独立的回收与预热页面，通过所选服务的
带版本校验接口保存，不混入前端偏好，不以本机配置替代不可用的远程服务。

## 会话切换的同步工作

用户反馈：点击另一个会话后会明显停顿，随后才显示内容。排查发现切换处理器在 UI 线程
序列化离开会话的完整历史以计算缓存预算，并同步保存已读状态和最后会话（含 `fsync`）。
这些工作会阻塞下一帧，不能通过延长动画或去掉缓存上限掩盖。保留现有历史／直播游标、
缓存预算和导航持久化语义，将耗时统计与文件写入移出切换的同步路径，分别回归验证。

历史载荷大小在连接任务接收时统计，UI 随分页、前缀保留和直播追加维护数字预算；
切换只读取总量，仍保留四个会话／32 MiB 的热缓存上限。导航选择与已读游标合并为
有序后台写入，保留 `fsync`、其他配置段和退出时的等待。合成测试单独比较旧的全历史
序列化与新缓存插入／取出，不把这项计时冒充完整会话加载或首帧耗时。

## 设置页反馈不附带复制操作

用户截图复现：智能体配置卡片中的“自定义配置”提示和设置侧栏底部自动附带复制图标，
即使底部没有提示内容也会留下一个孤立按钮。设置页统一使用不带复制操作的反馈展示，
保留提示正文、悬停全文和无障碍标签；不影响聊天、日志等其他界面的复制功能。
回归覆盖智能体卡片及空／非空侧栏反馈，使用原版组件，不修改依赖。

## 音频播放依赖

音频控件由 Bas 实现；解码与设备播放复用 crates.io 正式发布的
[rodio 0.21.1](https://docs.rs/rodio/0.21.1/rodio/)（MIT OR Apache-2.0）、
CPAL 0.16.0（Apache-2.0）和 Symphonia 0.5.5（MPL-2.0），具体版本由 Cargo.lock 固定。
Linux 通过 ALSA 动态库输出音频，GUI 的 Nix 构建、开发 shell 和运行包装共用依赖列表。
不复制或修改依赖源码，不引入 vendor 覆盖；第三方许可证不改标为第一方 MIT。

## 会话设置、输入提示与加载过渡

用户实测：删除确认混在“排版与输入”，placeholder 与正文颜色太接近，切换会话等待
历史时会闪现“发送消息，开始对话”。删除确认移到本机“会话”分类，复用现有偏好编辑
与保存逻辑；外观重置不影响会话偏好。输入提示和弱化操作使用同一颜色入口，
不改变真实输入、光标、选区或语法高亮。会话加载由当前 watch 状态和已收到的历史决定，
不加人为延时；重连保留已加载内容，失败不冒充空会话。

## 认证布局、会话操作与连接状态

用户实测：宽屏认证贴左边，与居中的输入区脱节，还同时显示空会话欢迎页；
登录方式纵向挤占空间。认证卡片改为复用会话内容列，登录按钮横排并在窄屏换行，
认证期间不显示欢迎页；回归覆盖宽屏与窄屏的对齐、换行和认证交互。

会话状态复用同一指示组件，不再用 gRPC 断线替代会话状态。服务器地址和连接状态
单独放在侧栏底部，与输入工具栏同行高、同基线。快捷键提示统一从绑定生成。
停止直接执行；归档必须先停止，恢复必须成功启动后才解除归档，失败保留原记录。
删除使用浮动确认窗口，可选择不再提醒，并可在设置中重新启用确认。

## 会话管理操作语义

窗口与入口统一称为“会话管理”，复用多对话气泡图标，避免历史时钟暗示只读历史。
卡片主要操作互斥：归档优先恢复，未归档且停止时启动，其余打开；不能同时展示
“打开”和“取消归档并打开”。打开使用对话气泡，启动使用播放三角，停止使用方块。
旧按钮回调必须重新检查状态，只执行当时标示的操作，不在状态变化后悄悄改派另一种操作。

## 会话状态与操作图标共用视觉入口

历史卡片的打开、恢复、重新启动、关闭、删除及刷新使用同一 `ui::icon_action`：
24px ghost 按钮、12px 图标、无可见文字、保留无障碍名称和用途提示。
状态指示迁移到 `ui::session_status`，会话侧栏与历史卡片调用同一渲染器：
启动／运行使用同色转圈，停止使用灰色熄灭灯，失败使用警告图标，就绪且已读留空。
归档是独立属性，使用被动归档图标而非拼接状态文字；状态提示不是可点击按钮。
历史窗口没有已读游标，不推断“未读”，侧栏继续保留自己的已读判断。

## Agent 历史会话状态与卡片

用户实测：历史窗口使用“查看 Bas 记录”等内部术语、重复展示 UUID，目录和操作分占多行，
Agent 筛选和计数位置不一致，关闭后的会话缺少重新启动入口。
历史卡片统一“打开”，省略 ID；下方目录与右侧操作同排。左侧统一“Agent／全部”，
数量紧邻右侧分组名称。“全部工作区”不使用具体目录的文件夹图标。
运行状态与归档分别展示，但归档必须停止运行；恢复加载原 ACP 身份并取消归档，
不自动发送消息。状态、恢复失败、并发重新启动及相同 ID 重新订阅事件流均需回归验证。

## 外观设置输入的一致性

将仅用于字体的控件模块收敛为整页共用的 `appearance/controls`：
字号、正文行高、不透明度共用数值步进、有效值展示和输入验证；
行高每次 0.1，不透明度每次 0.05，后者到 0/1 停止且允许完全透明。
备用字体、主题路径等文本覆盖使用同一位置的恢复图标；只有显式覆盖才显示，
空列表 `[]` 仍区别于继承。移除旧的文本“重置”按钮及第二套设置行布局。

## 字体设置的紧凑控件

字体设置参考用户提供的布局：用途说明放左侧，控件靠右；界面字体与字号放在同一行，
字号用共享的减小／可编辑数值／增大控件，默认状态显示实际生效值而不写入覆盖。
自定义字体或字号才显示恢复图标，恢复会清除相应覆盖并重新跟随主题，不硬编码默认值。
保留已有配置语义：正文沿用界面字体，正文和代码共用内容字号，代码单独选择等宽字体；
不为布局模仿增加没有实现的字体角色或连字开关。

## 设置关闭、会话导航与输入框菜单

用户实测：设置重复提供关闭按钮；虚拟时间线没有滚动条，分节导航贴窗口边缘而非
内容，末尾标记始终高亮；初始化草稿同时提供丢弃和删除；消息编辑器沿用代码菜单，
显示没有处理器的定义跳转与代码操作。
移除设置页关闭事件链，保留原生标题栏与快捷键的保存/关闭路径。时间线使用同一
ListState 驱动可拖拽滚动条、浏览位置与分节高亮，导航定位复用内容宽度容器。
草稿菜单仅保留丢弃，已有会话的删除仍确认。消息编辑器通过公开 context_menu
接口提供剪切、复制、粘贴和全选，保留原生 action 与附件粘贴拦截。

启动信息实际来自消息流，首次发送前的预览也复用 `content_panel`：
标题、消息、分隔线和输入区共享宽度限制，不再出现宽屏标题贴左而正文居中的分裂。
首条用户消息后仍保留原始消息顺序，不复制或丢弃启动输出。

智能体表单操作统一为左上返回箭头、左下删除图标、右下保存；新增未保存的智能体
不显示删除按钮。返回保持原先放弃编辑的行为，提示明确说明；删除仍先标记，再确认。

另收到附件预览加载失败及编号未重置的截图：现有确认发送流程会清空附件，新增回归
验证确认发送后重用首个标签、拒绝发送时保留原引用。尚未复现用户的图片解码失败，
需要失败原图及添加方式，不能仅凭其他图片解码测试通过就将此问题标为已解决。

## 会话导航快捷键与提示

原有 thread 操作快捷键没有出现在对应菜单和按钮提示中，Page Up/Down 聚焦
输入框时不能翻阅会话。现有菜单保留目标行回调，只补充按键绑定展示；
按钮提示同样从工作区 keymap 读取。Ctrl+Home/End 控制会话首尾，
Page Up/Down 使用虚拟列表公开的 viewport/scroll_by API，Ctrl+Page Up/Down
复用时间线轮次标记的用户消息到显示行映射，不按原始事件序号滚动。

## 会话输入区与状态持久化

用户截图复现：宽屏输出限制宽度并居中，但输入区铺满；输入框保留圆角四边框；
侧栏空闲状态只隐藏图标，外层按钮仍有 hover；已读游标只存内存，重开后历史回复
又显示未读。输入区与状态栏复用输出的 `content_panel`，输入边界改为顶部单分隔线，
不改编辑器原生输入行为。侧栏状态用非按钮元素展示，空闲留白不注册状态控件。

已读游标写入现有的按服务地址区分的窗口状态文件，与置顶及选择一起保留；
写入使用已有锁与原子替换，并合并各会话的最大已读游标。连续输出防抖，关闭和退出刷新。
新增 thread 快捷键调用既有重命名、归档、置顶、确认删除和工作区目录选择流程。

### Nix source 类型边界

可复现故障：首次 `make install-bas` 成功，再次安装或执行 `nix profile list` 时，
报 path URL 中 `submodules=1` unsupported。首次构建成功不能证明锁定 URL 可再次读取。
根因是全局 `inputs.self.submodules = true` 把 Git fetching 属性带入 path 快照的
锁定 URL，Nix 的 path fetcher 不支持该参数；参见
[Nix issue #13571](https://github.com/NixOS/nix/issues/13571)。

修复按 source 类型分界：移除全局 self 属性，只在 Git URL 显式请求
`submodules=1`；安装脚本的 path 快照已包含 `vendor/gds-uim` 源码，无需 Git fetching。
本地直接打包使用 `"git+file://$PWD?submodules=1#basg"`，远端输入使用
`git+https://github.com/4t145/bas?submodules=1`，不使用不支持子模块的 `github:` fetcher。
`nix develop .#gui` 加 Cargo 的工作流仍读取物理 checkout，需先初始化子模块。
真实 Nix metadata round-trip 与源码过滤回归见 [测试环境](testing.md#日常测试)。
更正源码不会自动修复已写入 profile 的坏记录；恢复步骤需单独验证，不应删除用户
profile 或数据来绕过此问题。

## 窗口排版与控制按钮的统一入口

智能体设置的截图还暴露了第一方组件重复：配置页与安装页各自构建名称、版本、
状态和操作区，前者没有图标且显示大标题，后者混用描边与文本按钮；安装流程结束后
又把“安装完成”保留在条目中。统一为共用智能体条目，版本与链接属于 `Entry` 的
前端展示方法，操作统一为带简短 tooltip 的 icon button。安装成功清除进度消息，
保留“已安装”的稳定状态；错误与认证信息仍各自有明确归属。添加与刷新只出现在
“智能体”章节标题旁，不放入导航或全局配置工具栏。

用户截图复现：主窗口常规文字使用 `0.875rem`，设置正文与导航曾分别落到
`1rem`；会话配置的 `xsmall` 选择按钮内部使用 `0.75rem`，导致旁边
`0.875rem` 的 Fast mode 标签看起来更大。只修改根节点的样式无法覆盖按钮的
内部文字规则。属于 BasG 的界面策略差异，不修改发布依赖的默认尺寸。

主窗口窗口按钮为 24×24 像素，图标为 12 像素；次级窗口原版 `TitleBar`
按钮为 34×34 像素，图标为 14 像素。`gpui-component 0.6.1` 的公开接口
不能替换其内建控制区，因此 BasG 使用第一方标题栏外壳与共享窗口控制组件，
保留公共窗口选项、拖动与最大化 API，不复制或修改依赖实现。

所有原生窗口使用 `theme::window_root`，控制区使用同一组件和主窗口的紧凑
规格。常规文字、会话选择标签与带标签复选框显式使用 `ui::SMALL`；消息与代码
仍使用独立内容字号。测试检查实际渲染标签的宽度／高度与窗口按钮边界，而非
只比较主题对象。设置框架及前后端配置边界见 [设置界面](settings-ui.md)。

## 鼠标悬停光标的交互语义

复现入口：主窗口的发送、附件、复制按钮，以及设置页的操作按钮。发布版
`gpui-component 0.6.1` 仅为 Link / Text 变体的按钮设置手型，普通和 Ghost
按钮默认为箭头；BasG 自绘的可点击行已有部分手型，因而同类操作反馈不一致。
直接给按钮构造器加 `cursor_pointer` 也会覆盖禁用／加载态，不能作为统一修法。

BasG 的策略是可用按钮显示手型，禁用、加载中的按钮和纯状态展示保留箭头；
可编辑／可选择正文显示 I-beam，正文中的链接优先显示手型。文本和链接继续使用
发布依赖的逐区域命中测试，不在正文外层设置手型，不把不可选择的说明文字伪装成编辑器。
按钮策略放在应用的共用 UI 层，继续委托原组件的视觉、焦点、键盘和点击处理；
不修改依赖源码，也不引入窗口管理器专用的光标控制。
可用开关、复选框和下拉选择器补上手型；紧凑窗口已有的拖动区域使用抓取光标。

验证：488 项 `gui-tests`、168 项 `gui` 测试、GUI 构建、全目标严格 Clippy、

### UI-005：Ctrl+Backspace 破坏图片占位符

用户拖入图片后按 Ctrl+Backspace，只删掉了占位符的右括号。该现象已在实际拖入事件的
headless 回归中复现。源码已补齐前后两个按词删除 action 的应用层保护：使用上游同一
Unicode 分词库确定候选范围，只在删除范围碰到附件时扩展为整个占位符；普通文本仍由
原生 action 处理。显式范围编辑保留 Undo 前的光标，而不是先制造临时选区再删除。

回归覆盖拖入图片、Ctrl+Backspace / Ctrl+Delete、中文和 emoji 前缀、空白、已有选区、
普通文本以及撤销恢复的文本、附件引用与光标。没有恢复 vendor 或修改依赖缓存。
此修复已包含在本地安装包；已打开的旧进程需要重新启动 GUI 才能使用新版。

### UI-006：文件选择时出现 Portal GetAll warning

用户在添加图片时实际观察到 `zbus::proxy` 的属性缓存 warning：
对 `/org/freedesktop/portal/desktop/request/...` 执行 `GetAll` 返回
`org.freedesktop.DBus.Error.UnknownMethod`，提示 Request 对象不存在。
这项日志问题已确认，尚未处理；目前没有据此确认图片添加失败。
不通过屏蔽整个 zbus 日志目标来假装修复。

### UI-007：远程图片报 No HttpClient available

根因是应用没有为 GPUI 注册 HTTP client，并非图片地址已返回错误。源码已在窗口创建前
接入正式发布的 Apache-2.0 HTTP 适配器，复用 GUI 的 Tokio 网络运行时，不修改 GPUI。
资源请求默认使用 30 秒总期限，覆盖响应体读取，并保留调用方指定的期限。

回归通过真实 GPUI `ImageAssetLoader` 加载 loopback SVG，验证解码、重定向、404 和停滞
响应体超时；GPUI future 从非 Tokio 执行器轮询，防止把运行时桥接错误藏在测试环境中。
没有在测试中请求用户提供的外部站点，也没有关闭 TLS 证书校验。
此修复已包含在本地安装包。

### UI-008：Mermaid 渲染（远期待办）

用户观察到 `mermaid` 未注册、语法高亮回退为 `text` 的 warning。按用户要求保留为远期
功能：当前 Mermaid fence 仍按代码块显示，没有图形渲染。注册一个高亮名称不等于实现
Mermaid 渲染，本轮不通过伪注册语言或屏蔽 warning 宣称完成。

### UI-009：线程右键菜单关闭后保留 Entity

使用发布版 `ContextMenuExt` 打开线程菜单并执行操作后，GPUI 回归在销毁窗口时报告
`PopupMenu` Entity 泄漏。其共享状态持有订阅，而订阅闭包又持有共享状态；关闭菜单
没有释放这条持有链。

应用不修改依赖，线程右键菜单复用 Workspace 已有的菜单所有权与关闭路径：
支持时使用原生 popup，否则使用窗口内 overlay。回归执行置顶、重命名、归档和
删除确认后销毁窗口，验证操作目标与生命周期；不关闭 GPUI 的泄漏检测。

### UI-010：紧凑窗口的动态 tooltip 被窗口边界裁切

复现：以最小宽度 420px 的 compact 窗口启动，令 Agent 初始化失败并在发送按钮上
停留至 tooltip 出现。将完整错误信息放在按钮提示中时，发布版 `gpui-component
0.6.1` 的默认单行 tooltip 可以超过窗口宽度；窗口内 overlay 无法显示超出原生
窗口的部分。长路径、无空格输出及多行错误也有相同风险。保持窗口内 overlay，
使用公开的 tooltip builder 限定宽高并允许换行/滚动，不改依赖或协议。

应用侧复用窗口尺寸约束的 hoverable tooltip：长 token 按 grapheme 插入零宽换行点，
内容区域可滚动，弹层仍在原生窗口内。回归通过实际鼠标移动及显示延时，测量
420×80、420×240、1120×800 三种窗口的长错误、多行提示，并直接检查 compact
发送按钮在初始化失败后的 tooltip 边界。当时 GUI 全套 171 项通过，UI-001、UI-002
两项既有断言仍失败；这两项现已由后续应用适配修复。真实桌面合成器
的视觉呈现仍需人工确认，headless 边界测量不等于实机截图。

### UI-011：Markdown 有序列表丢失非 1 起始编号

发布版 `gpui-base 0.6.1` 的 Markdown AST 到节点转换未保存 `mdast::List.start`，
渲染列表又从零开始计数。最小复现为 `3. third\n4. fourth`，显示编号成为 1、2。
多级有序列表还使用组件自己的字母编号策略。当前整表 Markdown 复制、多级列表、
列表内代码与表格回归不表示该编号问题已修复，也不能据此关闭 UI-003 的用户报告。
保留成熟的上游解析与布局实现，编号修复需要上游公开节点／渲染 API 支持。

### 删除后图片编号递增

当前草稿保留已删除附件的内容以支持 Undo，新的附件引用不会复用旧名字，因此删除
Image 后再次插入可能显示 Image 2。这不是当前正在发送的附件数量；发送时只使用
文本中仍存在的完整附件引用。若需要显示序号连续，应将展示序号与稳定引用解耦，
不能简单复用名字而令撤销后的引用指向另一张图片。

### UI-012：原生剪贴板只读取第一个匹配格式

发布版 `gpui-pre-linux 0.3.5` 的 Wayland 读取优先返回 UTF-8 文本，图片只在文本不存在
时读取；没有处理文件管理器的 `text/uri-list`，也未将纯 `text/plain` 作为文本回退。
macOS pasteboard 同样优先文本。直接在 headless 注入多项 `ClipboardItem` 无法复现
平台层丢格式的问题。

应用用发布版 [wl-clipboard-rs](https://docs.rs/wl-clipboard-rs/0.9.4/wl_clipboard_rs/paste/index.html)
与 macOS [arboard](https://docs.rs/arboard/3.6.1/arboard/struct.Clipboard.html) 补充原生读取，
保留同时存在的文字和图片，读取本机文件 URI；Windows 保留 GPUI 原有多格式路径。
读取放在后台，有三秒应用期限和单项读取大小限制，不阻塞输入 UI；期间输入和发送禁用。
草稿代次与内容快照共同防止 thread 切换、队列编辑或程序修改草稿后的迟到结果混入。
合成器没有 data-control 或读取失败时回退到已有 GPUI 内容，不宣称回退仍覆盖所有 MIME。

`tests/wayland_clipboard.py` 建立独立 headless Sway，实际提供纯 `text/plain`、
文本与 PNG 并存、文件 URI 三种 offer 并读取验收；不会覆盖用户当前桌面的剪贴板。
headless Workspace 回归检查发送／输入拦截、失败回退与 Undo、切换后丢弃、首次初始化
保留粘贴，以及图片不受支持时仍保留文字。macOS 实机 pasteboard 与 Windows 外部来源
粘贴仍需对应平台桌面验收。

### UI-014：ACP 目录以首字母替代真实图标，thread 缺少后端标识

共享目录元数据按 daemon 地址隔离，支持将自定义 `pi` 的 `pi-acp` 启动器关联到官方标识。
侧栏按 `session.agent` 取图标，新 thread 草稿和选择按钮按实际选中的后端显示。
回归覆盖真实 SVG 与位图、深浅主题、失败回退、内置资源、身份匹配和行内布局稳定性。

### UI-015：已有会话的 Agent 按钮仍能打开选择菜单

写入 disabled 属性；因此用实际点击、菜单是否打开和是否发送 RPC 验证禁用行为，

现已在已有会话及创建期间禁用按钮，并在内部处理选择的入口添加同样的守卫。
显式新 thread 的选择草稿不受目录刷新或 F5 自动创建；目录“开始对话”仍能创建
独立的新会话并保留旧草稿。创建和等待认证期间，旧目录快照不会覆盖已选 Agent。

### UI-016：Fast mode 使用泛用齿轮，检测和登录状态含糊

用户实机看到 Codex Fast mode 以齿轮表示，缺少速度模式的语义提示。目录同时显示

Boolean 配置项应显示名称与原版 Switch，直接表达当前开关状态，无需推断后端名称
或配置 ID 的图标含义。目录分别显示安装、检测结果与登录需求，并提供独立的检测

# 组件定制化

考虑到各方的gpui使用者都进行了不同程度的定制化，定制化似乎看起来是可以接受的。但是不要用vendor进来的形式去做。要做就要做一个general的。我们只针对性的解决目前zed家gpui的通用性较差处的问题，并且考虑定期向上游提出合并。

长期目标：我们仍然考虑基于gpui生产更多的native桌面软件。比如文件管理器等，也可以支持sonora之类的音乐播放器的建设。

# 输入框呈现
输入框也是一个很关键的地方，目前做的已经七七八八了。

输入框可能还需要做一些优化

1. 剪贴板，是否对于各个平台的剪贴板支持全面需要检讨
2. 多行输入和单行输入的切换。有时候可能是一些简短提示词，有时候可能是多行，不同的情况下发送方式也要有所改变

## 修改与撤回机制
在缓冲区的消息可以修改或者撤回，缓冲区消息应该放在消息面板的最下方（类似zed agent panel的设计）

也可以立即发送，也就是所谓的打断/发送流程


# thread内容呈现
thread内容呈现的核心应该在于用户的消息和agent返回的结论性blocks

对于工具调用和思考块应该弱化

一个常见的非编码agentic 任务通常可能有这些结构：

1. 用户的一次输入
2. 思考+连续的多次工具调用
3. 输出块

视觉上应当突出用户输入和ai content性质的输出，弱化中间的部分。因此，连续的工具调用应当是可以作为一整个block来折叠的。

简化语言可能是一次思考，n次工具调用之类的hint, just like zed's agent panel.

## markdown渲染
markdown渲染如果long bridge的ui组建库支持不足，可以自己去做一套

作为computer use类的反馈输出可以不那么强调文档式的排版效果。但是对于markdown中的各种结构性要素如多级列表，表格之类的，必须要有比较好的支持

## 特殊渲染
一般来看特殊渲染可能有这么一些需求
1. mermaid，流程图渲染，这个目前好像zed都没有支持，可以后面做
2. diff，一阶段不重要
3. terminal input/output。这个在ccomputer use的场景很重要。可以参考delta的按下`!`切换到一个真实终端的伟大设计。
![delta中的终端渲染](image.png)
4. approval 这个比较关键。
5. tex公式，这个离开js似乎比较难办。。。需要考虑rust有没有原生的tex公式渲染库。
6. typst,考虑到可以直接调用库难度应该小于tex,问题是ai不会乐意可能也不是很知道如何输出tex公式，需要实验

# 跨平台
首先支持linux + wayland的环境。其次支持macos/win11, 本身gpui的跨平台能力是有保障的。问题可能在于ui界面的设计。比如wayland下可能不太需要关闭与最大化这些按钮。macos下面可能是信号灯，windows下面的用户比较依赖最大化，缩小，关闭这一组按钮。在wayland下也不好发现尺寸改变导致的显示bug

# 实现与验收（2026-10-09）

本轮落实应用侧交互和平台适配。按当前范围，特殊内容渲染和自研 Markdown 不新增；
Markdown 继续使用发布版 GPUI Base，已有标准 ACP 审批继续保留。

| 要求 | 实现与验证 |
| --- | --- |
| 通用组件定制，不 vendor | 只用公开 API；输入布局与工具栏对齐分别封装为测量适配。原版依赖问题与最小复现见 [上游记录](../upstream-ui.md) |
| 剪贴板 | Wayland 补齐纯文本、文本与图片并存、文件 URI；macOS 补齐多格式读取；Windows 使用 GPUI 原生读取。异步读取有期限，失败回退，草稿切换后丢弃迟到结果 |
| 单行／多行发送行为 | 设置中持久化 Enter 发送／换行；Alt+Shift+Esc 展开多行编辑器，Ctrl+Enter 或 macOS Cmd+Enter 发送；切换保留草稿、附件和焦点 |
| 缓冲消息编辑与撤回 | 队列位于消息面板底部；任意条目可修改、撤回，取消编辑恢复原草稿 |
| 打断并立即发送 | 先取消当前回合，等待取消确认与回合结束后发送；失败保留队列，单条发送不恢复其余暂停项 |
| 突出用户输入和 Agent 输出 | 用户消息独立呈现；连续思考和工具调用默认归入折叠活动块，摘要显示思考、工具、执行中和失败数量 |
| Markdown 结构 | 保留上游多级列表、表格及整表复制；非 1 起始有序列表编号限制继续记录为 UI-011，不以本轮测试通过宣称已修复 |
| 窗口能力与 resize | 按平台能力显示窗口控制，macOS 使用原生信号灯；回归覆盖两种模式、窄／宽窗口、混排、字号变化及工具栏起点对齐 |
| 跨平台数据目录与构建 | 统一使用系统用户配置／状态目录，仍接受绝对 XDG 覆盖；CI 增加 macOS、Windows 原生构建及桌面状态测试 |

Linux GUI 回归和独立 Wayland MIME 检查可在本机执行；macOS、Windows 的原生 CI
以及实机输入法、缩放、合成效果属于对应平台验收，不能用 Linux headless 结果替代。
复现命令与目录规则见 [GUI 说明](../gui.md)。向上游提交修复和构建其他桌面应用属于长期工作，
本轮提供可复现记录与应用适配，不自动向外部仓库提交 issue 或 PR。

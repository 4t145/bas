# 服务连接类型

Bas、BasT 和 BasG 共用连接目标格式。Bas 和 BasT 默认使用同一系统用户的本地 IPC，
不需要配对，也不默认监听 TCP。BasG 默认使用前端保存的所选连接；尚未配置时同样是 `local`。
远程 mTLS 支持手动提供证书和密钥文件，见 [mTLS 配置说明](mtls.md)。
扫码配对仍在[远程接入规划](design/remote-access.md)中，尚未实现。

## 默认本地连接

```sh
bas
bast agents
basg
```

首次使用时，三者都默认使用 `local`：

- Unix：使用用户私有目录中的 Unix socket，验证文件权限和双方的系统用户身份。
- Windows：使用当前用户 SID 对应的本地 Named Pipe，通过用户 ACL 和双方身份检查建立连接。
  不允许远程 Named Pipe，也不把同名管道直接视为可信服务。

本地连接失败时不回退到 TCP。服务端以哪个系统用户运行，就由该用户的本地客户端连接；
系统服务以独立账号运行时，不能因为客户端也在这台机器上就自动获得访问权。

Unix 默认使用 `$XDG_RUNTIME_DIR/bas-<uid>/service.sock`；没有运行时目录时使用系统临时目录下的
`bas-<uid>/service.sock`。服务端与客户端需要使用同一运行时目录，否则应显式指定 socket。
仓库的 systemd 系统服务模板使用 `/run/bas/service.sock`，同用户客户端需指定
`--server unix:///run/bas/service.sock`；用户服务仍使用默认 `local`。

所有获准客户端访问同一个服务实例的共享执行环境。本地免配对不引入额外的 Bas 用户体系。

## 在 BasG 中管理和切换服务

1. 使用 `Ctrl+,` 打开设置，在“前端 → 服务连接”点击右上角 `＋`，选择“手动添加”。
   选择连接类型，填写名称及可选备注；TCP 填写 IP 或主机名和端口，本地 socket / 管道填写对应路径或名称。
   本地自动连接不需要填写地址。
   mTLS 另需填写 CA、客户端证书及私钥文件路径，不将密钥内容保存到配置中。
   可点击这三个路径框旁的文件夹按钮选择本地文件，或直接编辑路径；预期服务名称仍为普通文本输入。
   选择文件不会读取证书内容或立即保存设置，需点击保存才写入路径。取消选择保持原值；
   关闭编辑器或切换连接类型后，尚未完成的选择不会填入新的编辑器。
   类型菜单按当前系统过滤：Linux/macOS 提供本地自动、TCP、mTLS 和 Unix socket；
   Windows 提供本地自动、TCP、mTLS 和命名管道。已有的跨平台连接配置仍保留，不会被自动删除。
2. 点击“添加”或“保存”只更新连接配置，不切换正在使用的服务。
   在连接卡片上点击勾选图标，才将它设为管理目标和下次启动默认值；
   铅笔图标展开编辑，`Esc` 或关闭图标取消，垃圾桶图标确认后移除。至少保留一个连接。
   连接页支持 `Ctrl+N`（macOS 为 `Cmd+N`）手动新增，输入框中按 Enter 保存。
   保存后可点击卡片上的“检查连接”测试连通性，结果显示在该卡片内；mTLS 同时检查证书认证。
   检查最多等待 5 秒，不改变所选服务。修改地址或证书路径后，原检查结果会清除。
3. 在后端的 Agent 服务配置页，通过顶部下拉框切换要管理的服务。
   不同服务的编辑草稿、安装、检查和认证状态分别保留，不把旧服务的结果写到新服务。
4. 会话窗口底部显示状态点、连接方式图标和服务名称。展开后可查看各服务的具体地址，
   并在当前窗口切换；各服务的会话和未发送草稿分别保留，切回来可继续使用。
   菜单与设置卡片都采用“图标＋名称、地址”的信息层级；设置卡片另显示可选备注，协议说明放在悬停提示中。
5. “打开会话窗口”和 Agent 设置中的“开始聊天”会优先复用包含该服务的窗口；
   尚无对应窗口时才新开窗口。底部的服务切换菜单始终在当前窗口内切换。

删除保存的本地连接后，可通过 `＋ → 发现本地服务` 重新发现。发现只探测当前用户的
`local` 默认端点，使用现有的同用户身份验证和只读 RPC，最多等待 3 秒；
不会扫描目录、LAN 或 mDNS，也不会回退到 TCP。成功后显示实际地址，须点击“添加”才保存，
不会自动切换管理目标。已有 `local` 或等价的默认 socket / pipe 时显示“已添加”。
关闭发现面板会取消探测；未找到已验证的服务时可重试，不会安装或启动服务。
“本地（自动）”是平台默认 IPC：Unix 上是 Unix socket，Windows 上是命名管道；
显式 Unix socket / 管道选项则用于手动指定其他端点，不属于自动发现范围。

连接列表存放在前端的 `settings.json`，与后端的 Agent 注册分区保存。例如：

```json
{
  "frontend": {
    "selected": "local",
    "connections": [
      { "id": "local", "name": "Local", "target": "local" },
      { "id": "work", "name": "工作站", "note": "用于日常开发", "target": "tcp://workstation" }
    ]
  }
}
```

这里的 `id` 是稳定配置标识，修改名称、备注或地址不需要更换 ID。`note` 可省略；
界面以普通只读文字显示备注，不附加复制按钮；悬停可查看完整内容。
编辑时留空则不保存该字段，备注不参与连接身份或路由。连接检查结果和错误仍可复制。
移除配置不删除服务或会话。
启动参数 `--server` 优先于 `BAS_SERVER`，两者都优先于保存的默认连接，且不会自动改写配置。
从已有聊天窗口打开设置时，管理目标跟随该窗口，但不会因此覆盖保存的下次启动默认值。

GUI 通过所连接服务的 RPC 读取和保存 Agent 配置，本地与远程使用同一编辑器。
保存只修改服务端的 Agent 配置段；其他客户端同时修改时，需重新读取后再保存。
TCP（包括回环地址和端口转发）的服务端路径不会作为本机文件打开。
Agent 交互认证在服务端执行；需要本机终端的认证方法仍需在服务所在主机完成。

升级时需同时更新读取同一配置的 daemon 和 GUI：旧版严格 JSON 解析器不认识新增的
`frontend` 字段。旧配置省略该字段时自动使用默认本地连接，读取本身不会改写文件。

## 显式选择连接类型

| 目标格式 | 含义 |
| --- | --- |
| `local` | 当前用户在当前平台的默认本地 IPC |
| `unix:///absolute/path/service.sock` | 指定 Unix socket；只在 Unix 平台可用 |
| `pipe://bas-work` | 指定本地 Windows Named Pipe 名称；只在 Windows 可用 |
| `tcp://127.0.0.1` | 显式使用明文、无认证 TCP |
| `mtls://workstation:7338` | 双向证书认证 TLS，需显式提供证书文件 |
| `127.0.0.1` / `[::1]` | 不带协议前缀的 TCP 地址 |
| `tcp://workstation` / `workstation.tailnet.ts.net` | 通过系统解析器连接主机名 |

TCP 支持系统 DNS、hosts 文件和已配置的 Tailscale MagicDNS；不依赖 Tailscale。
配置解析和加载时不查询 DNS，连接（含重连）或绑定监听地址时才由系统解析。
TCP 和 mTLS 的端口可省略，统一使用 [`DEFAULT_PORT`](../src/service/defaults.rs) 定义的默认端口，例如 `workstation`、
`tcp://192.0.2.10` 或 `mtls://workstation`。显式端口必须为 `0` 到 `65535` 的数字；
监听端口 `0` 会报告实际分配的 IP 和端口，不会被替换为默认值。
IPv6 必须使用方括号，例如 `tcp://[::1]` 或 `tcp://[::1]:7443`。
省略端口与显式填写默认端口使用相同连接身份和状态文件；配置和传输保留完整端口，
界面可省略默认端口，但不会省略非默认端口或 `0`。
地址不能包含凭据、路径、查询、片段或空白。
主机名（包括 `localhost`）不代表同用户身份或本地文件权限，也不会自动启用 TLS。

`pipe://` 后面是本地名称，不是远程主机或 UNC 路径。Unix socket 所在目录必须属于当前用户、
仅该用户可访问；不会自动放宽已有目录的权限。

客户端使用 `--server` 或 `BAS_SERVER` 选择一个目标，命令行优先：

```sh
bast --server local agents
basg --server pipe://bas-work
bast --server tcp://192.0.2.10 agents
bast --server tcp://workstation.tailnet.ts.net agents
```

## 启用 TCP 或多个监听入口

TCP 是保留的可选传输，显式选择即可使用，不需要额外的确认开关。
TCP 不提供加密或客户端认证；回环 TCP 也不等于已认证的本地用户。
连接者可使用同一服务的配置、安装、登录和会话接口；明文 TCP 也不提供用户间隔离。

只监听 TCP：

```sh
bas --listen tcp://127.0.0.1
bast --server tcp://127.0.0.1 agents
```

同时提供本地 IPC 和 TCP：

```sh
bas --listen local --listen tcp://127.0.0.1
```

每个入口访问同一个会话注册表和执行环境。`--listen` 可以重复指定；
`BAS_LISTEN` 使用分号分隔多个目标，例如 `local;tcp://127.0.0.1`。
显式提供监听配置会替换默认的 `local`，不会隐式再打开其他入口。
任一指定入口绑定失败都会使启动失败，不静默忽略配置。

## 从原有 TCP 默认值升级

- daemon、CLI 和 GUI 的默认值一起改为 `local`；更新双方后，同一用户无需配对即可使用。
- 已有 `--listen`、`--server`、`BAS_LISTEN`、`BAS_SERVER` 的显式 TCP 设置继续有效，
  不会被自动改写或禁用。
- 新客户端连接仍使用 TCP 的旧 daemon 时，需显式设置 `--server 127.0.0.1`；
  旧客户端连接新版 daemon 时，可以显式开启对应 TCP 监听。
- 不会在本地 IPC 失败时自动连接旧 TCP 地址。
- GUI 保留原有 TCP 目标的导航状态文件名；IPC 目标有独立状态，不把不同连接类型的
  当前会话、书签和未读游标混用。`local` 与它解析出的具体 socket / pipe 共用导航状态。
  会话数据库和服务端历史不会因改变传输类型而迁移或删除。
